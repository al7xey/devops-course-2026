# Git и SVN

**1. Почему в Git ветвление "дешёвое", а в SVN "дорогое"?**

В Git ветка - это просто файл с хешем коммита (указатель), создать её можно мгновенно и локально. Файлы при этом никуда не копируются. В SVN ветка делается через `svn copy` директории trunk в branches на сервере, то есть это отдельная копия в репозитории, нужен сервер, а слияние потом заметно сложнее.

**2. Можно ли в SVN сделать коммит без интернета?**

Нет. В SVN история хранится только на центральном сервере, а у разработчика лежит рабочая копия одной ревизии. Коммит - это запись на сервер, поэтому без связи с ним закоммитить нельзя. Можно только менять файлы локально и ждать подключения. В Git вся история есть локально, коммиты делаются офлайн, а push потом.

**3. Когда SVN может быть лучше Git?**

- Репозитории с большим количеством больших бинарных файлов (геймдев, дизайн, CAD) - не нужно тянуть всю историю, можно выкачать только нужную папку.
- Когда нужна блокировка файлов (lock), чтобы два человека не правили один бинарник одновременно.
- Нужны права доступа на уровне отдельных каталогов.
- Старые проекты, где всё уже построено вокруг SVN и переезд не окупится.
